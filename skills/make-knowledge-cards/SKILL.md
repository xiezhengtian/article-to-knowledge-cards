# Make Knowledge Cards（知识卡片生成）

## Overview

把一篇文章提炼为 5~8 张"一卡一知识点"的学习卡片。卡片只承载原文中真正重要的知识，
用原文支持的内容作解释和例子，绝不编造原文没有的信息。

## 输入获取

- 用户直接粘贴文章 → 以消息正文为输入。
- 用户给出本地文件路径 → 用 Read 工具读取 `.md` / `.markdown` / `.txt` 文件。
- 两种输入都拿不到有效正文（如文件不存在、内容为空、内容是二进制乱码）→ 停下来
  告知用户，不要凭空猜测文章内容。
- 明确不支持：网页 URL 抓取、PDF、Word、Anki、图形界面。用户提出这些时，请用户
  先把文本复制粘贴过来或另存为 TXT/Markdown。

## 工作流程

1. **通读全文**：先完整读一遍，判断文章的主题、类型（技术/科普/教程/观点文等）和
   信息密度。
2. **圈定知识点**：从原文中挑出最重要的知识点。判断标准：
   - 是理解全文必需的核心概念、原理、步骤或结论；
   - 是作者用大量篇幅强调或反复出现的内容；
   - 排除：寒暄、转场语、营销话术、纯背景八卦、与主题无关的旁支。
3. **一卡一知识点**：每张卡片只讲一个知识点。如果一个知识点有多个独立子概念且都很
   重要，拆成多张卡片，而不是塞进一张。
4. **去重**：原文中重复出现、或表述不同但含义相同的内容，只保留一张卡片，在解释里
   合并各种说法。不要为凑数量把同一知识点拆成两张近义卡片。
5. **定数量**：
   - 优先产出 5~8 张；这是目标区间，不是硬性下限。
   - 原文信息量不足以支撑 5 张有内容的卡片时，产出更少（哪怕只有 2~3 张），并在
     输出末尾用一句话说明"原文信息量有限，只提炼出 N 张卡片"。
   - 原文通篇没有任何成型的知识点（如流水账日记、纯寒暄）时，不输出卡片，明确告知
     原因，并请用户提供信息密度更高的内容。此时同样不得编造或把琐事硬写成知识点。
   - 禁止为了凑满 5 张而拆分同一知识点、收录琐碎细节或编造内容。
6. **写卡片**：按下面的卡片模板逐张撰写。
7. **输出**：以 Markdown 直接输出全部卡片（不要写入文件，除非用户明确要求保存）。

## 卡片模板

每张卡片使用以下固定结构：

```markdown
## 卡片 N：{标题}

**核心知识**：{一句话说清这个知识点本身}

**简明解释**：{2~4 句展开：它是什么、为什么重要/怎么用。全部基于原文}

**例子**：{原文中的具体例子、数据或场景}
或
**自测**：{一个能从原文找到答案的问题，并附简短答案}
```

写卡规则：

- **标题**：直接点出知识点（如"TCP 三次握手的作用"），不用"第一个知识点"这类空标题。
- **核心知识**：一句话，信息完整，能脱离卡片单独成立。
- **简明解释**：只解释这个知识点；用原文的概念和逻辑，可以换自己的话复述，但不得
  引入原文没有的事实、数字、名词或结论。
- **例子/自测**：每张卡片二选一，交替使用更利于复习。
  - 例子优先取原文现成的例子、代码、数据、场景；
  - 自测问题必须能在原文中找到明确答案，并附上答案；
  - 原文没有任何可用例子、也提不出可回答的自测问题时，写"（原文未提供例子）"，
    不要现编。
- 原文出现的专有名词、数字、单位、代码必须原样保留，不得改写或"近似"。

## 忠实性红线

- 不编造：卡片里的每个事实性陈述都必须能对应到原文。
- 不过度推断：原文说"可能与 X 有关"，卡片不能写成"X 导致 Y"。
- 不补外部知识：即使知道原文错了或过时，也不在卡片里悄悄替换成外部知识；如有必要，
  在所有卡片之后单独加一条"与原文不一致的提示"并明确标注这是卡片之外的补充。
- 信息不足时宁可少做，不强行凑数。

## 输出收尾

全部卡片输出后，附一小段收尾（2~3 行以内）：

- 卡片总数，以及若少于 5 张，说明原因；
- 提示用户可以要求调整：增删主题、改成自测模式（隐藏答案）、导出保存为文件。

## 明确不支持

- 网页抓取（URL → 卡片）：请用户粘贴正文。
- PDF / Word / 图片 OCR。
- Anki 或其他记忆软件的导入格式导出。
- 图形界面 / 可视化卡片渲染。

用户提出以上需求时，说明当前仅支持纯文本与 Markdown/TXT 文件，并引导提供文本。
