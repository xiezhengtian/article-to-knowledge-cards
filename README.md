# git

个人代码工作区。当前包含一个 Skill：**make-knowledge-cards（知识卡片生成）**。

## 一、项目解决什么问题

读文章容易，记住难：一篇长文读完，往往只留下模糊印象，复习时也不知道该看哪些重点。
本项目的 Skill `make-knowledge-cards` 解决的是**文章内容的学习与复习问题**——
把一篇粘贴的文章或本地 Markdown/TXT 文件，自动提炼成 5~8 张"一卡一知识点"的知识卡片，
让重点明确、可逐张复习。同时它解决 AI 总结的常见痛点：**编造与凑数**——卡片内容
严格忠于原文，信息不足时宁可少做也不硬凑。

## 二、主要功能

- **知识卡片生成**：每张卡片固定包含四要素——标题、核心知识、简明解释、例子或自测问题
- **一卡一知识点**：重要子概念自动拆分为多张卡片，不做大杂烩
- **智能筛选**：只提取真正重要的知识，剔除寒暄、转场、营销话术等噪声内容
- **去重合并**：原文重复出现或近义表述的内容只保留一张卡片
- **数量自适应**：目标 5~8 张；信息不足时自动减少（哪怕 0 张并说明原因），绝不强行凑数
- **自测模式可扩展**：卡片中的自测问题附答案，可要求隐藏答案用于复习

支持的输入：直接粘贴的文章文本、本地 `.md` / `.markdown` / `.txt` 文件。
暂不支持：网页抓取、PDF、Anki 导出、图形界面。

## 三、安全方法

- **忠实性红线**：卡片中每个事实性陈述必须能对应到原文，不编造原文没有的信息、数字或结论
- **不过度推断**：原文说"可能与 X 有关"，卡片不会写成"X 导致 Y"
- **不引入外部知识**：即使发现原文有误，也不会悄悄替换成外部知识；如需提示，会在卡片之外单独标注
- **本地处理**：仅读取本地文本文件（`.md` / `.txt`），不联网抓取网页，不上传文章内容到第三方服务
- **文件安全**：默认只在对话中输出卡片，不写入任何文件；除非用户明确要求保存
- **明确的边界声明**：不支持的输入类型（网页、PDF 等）会被明确拒绝并引导用户换方式提供文本，而不是猜测处理

## 四、使用方法

把文章直接粘贴给 AI 助手，或给出本地文件路径，然后说：

```
帮我把这篇文章做成知识卡片
```

也可以指定文件：

```
把 D:\notes\http-cache.md 转换成知识卡片
```

在支持 Skill 调用的环境（如 Codex CLI）里可显式触发：

```
$make-knowledge-cards
```

Skill 安装位置：

```
skills/make-knowledge-cards/
├── SKILL.md           # Skill 主文件（触发条件、工作流程、卡片模板、忠实性红线）
└── agents/
    └── openai.yaml    # UI 元数据（展示名、简介、默认提示词）
```

## 五、输入输出示例

**输入**（用户粘贴文章）：

```markdown
# TCP 三次握手详解

建立 TCP 连接需要客户端和服务器交换三个报文，俗称"三次握手"。
第一步，客户端发送 SYN 报文，其中携带一个随机初始化的序列号 x……
第二步，服务器收到 SYN 后，回复 SYN+ACK 报文，它的序列号是另一个随机值 y，
确认号则是 x+1……
```

**输出**（AI 生成的知识卡片）：

```markdown
## 卡片 1：三次握手的报文顺序

**核心知识**：TCP 建立连接需依次交换 SYN → SYN+ACK → ACK 三个报文。

**简明解释**：客户端先发 SYN（携带随机序列号 x）；服务器回 SYN+ACK
（序列号 y，确认号 x+1）；客户端最后回 ACK（确认号 y+1），连接建立完成。

**自测**：服务器回复的确认号为什么是 x+1？（答案：表示已收到序列号 x 及
之前的字节，期望下一个字节是 x+1。）
```

**输入**（信息量不足的文章，如流水账日记）：

```text
今天天气不错，我出门买了杯咖啡……总之是普通的一天。
```

**输出**：

```markdown
（不输出卡片）原文通篇没有成型的知识点，无法提炼知识卡片。
请提供信息密度更高的文章内容。
```
